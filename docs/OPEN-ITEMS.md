# Open items: should we do them?

For every item that is still open after 1.0.0-rc.2: what was measured or found out (not guessed), what it would cost, and a verdict.
Verdicts: **done** - fixed while looking; **do next** - worth it, not yet done; **only if** - worth it when a stated trigger happens;
**no** - not worth it, and why. Dated 2026-11-04; the probes behind the numbers were throwaway CI jobs (not kept).

| # | item | evidence | verdict |
|---|---|---|---|
| 1 | Tcl and Tk sources were downloaded **unchecked** (and over plain HTTP) | KitCreator's checksum table stops at 8.6.14; for 8.6.16 it uses hash `-` (no check). Our scripts claimed everything was pinned. | **done**: `tools/seed-tcl-sources.sh` fetches both over HTTPS and compares SHA-256 (taken from the SourceForge files when pinned: the Tcl project publishes none) before KitCreator runs. Metakit, tclvfs, itcl and zlib were already checked. |
| 2 | Move the runtimes from Tcl/Tk 8.6.16 to **8.6.18** | 8.6.18 (2026-05-11) is the last 8.6 release; since 8.6.17 the fixes are crashes, hangs and undefined behaviour (e.g. a crash on exit on Windows, `Tcl_SplitList` on huge strings, a Windows use-after-free in threaded `glob`); no CVE found. | **do next**: one hash line, a rebuild of the three runtimes, a full CI run - bundle it with the next release candidate. |
| 3 | Lock: two processes reaping one abandoned takeover guard both get in | Reproduced on demand (`tests/test_lock_crash.tcl`, "two reapers of one abandoned guard"): both ended up inside, and the second destroyed the first one's new lock (the commit-time check then let only the later one save). | **done** (rc.3): the takeover no longer deletes the lock by name; it moves it aside with one atomic rename, judges the *moved* file and puts a live lock back; a process re-reads its lock after writing it. The same test now requires that the two are never inside together; so do the starved-process tests that used to end in an overlap. Chaos soak with freezes and shortened limits: 8,425 acquisitions, 0 violations (Linux; the CI soak on the Macs is manual). Done in mkit-sql too (0.4.1). What remains needs three processes and microseconds, and the commit-time check covers it - see `docs/CONCURRENCY.md`, "What is left, honestly". |
| 4 | Operating-system file locks (flock / LockFileEx) for real mutual exclusion | With the native library in place the C is there (`flock` / `LockFileEx` are a few lines each). But the takeover fix (item 3) already closed the window that mattered, what is left needs three processes and microseconds and is caught by the commit-time check, and an OS lock would protect only MK Studio instances (not mkit-sql in a plain `tclsh`, not other programs). | **no** for now; **only if** the CI soak (which can be run on the Macs by hand) ever shows another overlap. |
| 5 | **Native flush** (a small C library) instead of starting programs | Measured before: on Windows every flush started PowerShell, **0.36-0.7 s each, three per save**, hidden, with an encoded command - what malware does; on macOS `sync` cannot reach the drive's cache. | **done** (rc.3): `native/mksync/mksync.c` (`fsync` / `fcntl(F_FULLFSYNC)` / `FlushFileBuffers`), built by CI for the three systems (stubs-linked: one binary for every Tcl 8), carried in the starpack, loaded when present, with the old programs as fallback. Tests: `tests/test_mksync.tcl` on all three systems (also loads into Tcl 8.5 and 8.6.3), the starpacks are checked to carry it and to report `flush native (...)`. The persistent PowerShell helper: no. |
| 6 | A real crash-consistency test (block-level, any write cut) | Hosted Ubuntu runners have `dm-flakey` and `dm-log-writes` loaded, loop devices, and mount ext4 on a mapped device (probed). The replay tool (`replay-log`, from xfstests) is not installed and would have to be built; not tried end to end. | **do next**, time-boxed (half a day to a day): it is the only way to test the commit protocol against a real filesystem's write ordering instead of our model. Linux and ext4 only. |
| 7 | macOS arm64 power-loss test crashed once (one run in about eight) | 38 further runs (14 seeds of the failing scenario + 5 seeds of three scenarios, on each of both Macs) and 11 seeds on Linux: **no failure**. The test now prints what differs about a failing candidate. | **only if** it recurs (then the printed byte differences say what it is). |
| 8 | macOS lock overlap on the Intel runner | Item 3 is the cause. | covered by 3 |
| 9 | Code signing | **A starpack cannot be signed as it is**: appending even 6 KB after the payload (what an Authenticode signature does) makes the program fail to start (tested). Only the Windows *installer* can be signed. Options (not verified in detail, prices change): SignPath Foundation (free for open source, needs approval and a CI integration), Azure Artifact Signing (about $10 a month, individuals only in the USA and Canada), an OV certificate ($150-300 a year). macOS: $99 a year plus a different bundle layout. | **no** for now; **only if** you hand the program to people who cannot be told to click "Run anyway" - then sign the installer via SignPath. |
| 10 | mkit-sql: the patch (unreadable lock, Windows flush, installer script) and a LICENSE file | Verified on a copy of 37847c1; push access was then granted. | **done**: mkit-sql 0.4.1 (branch `ccr-f017368d-kguqg8` of `atyr647/mkit-sql`, descends from its default branch, **not merged** - merge it, or open the pull request, when you have looked) carries the patch, the takeover fix, `LICENSE` (MIT), a new test file and a clean-up (a stray empty file named `&1`, a committed `.pyc`); it is vendored here. Its Windows flush follows MK Studio's until the native flush (item 5) exists. |
| 11 | mkit-sql gaps: result cap 100,000 rows, `ORDER BY ... LIMIT` ~4 s, scattered `DELETE` ~29 s (README has the table) | Its own storage is the cause (it does not use `store::deleteRows`, and returns materialised results). | **no** adapter here; raise it in mkit-sql. `MKS_ENGINE=mkql` is the workaround; a menu switch would need a restart - **only if** someone asks. |
| 12 | Drop Tcl 8.5 / 8.6.3 support | It is mkit-sql's stated target; costs a few CI minutes and some workarounds, not user-visible. | **no** (revisit when mkit-sql drops it). |
| 13 | Checksum and backup for files above 512 MB | Metakit's file limit is 2 GiB; a CRC pass costs ~3 s per commit at that size and the backup needs the same space again. | **no** (documented). |
| 14 | Hard links to a database taking a second lock in another process | Rare; the in-process case is refused. | **no** (documented). |
| 15 | Build supply: KitCreator comes from a one-person server (pinned revision, 310 KB); caches expire after 7 days unused | A rebuild needs the network. | **do** when next touching the build: keep the pinned tarball in the repository. Low priority. |
| 16 | CI actions on Node 20 (forced to 24 with warnings) | Works today. | **do** at the next workflow edit (bump the action majors; versions could not be looked up - API rate limit). |
| 17 | Screen-reader support | Tk has no accessibility API. | **no** (documented). |
